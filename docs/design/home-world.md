# ホームワールドとランチパッド（ロビーの撤廃）

ロビー（`/` の一覧画面）をなくし、ログインしたら自分のホームワールドの部屋へそのまま入る。
ワールドを探す・部屋を移る・設定などは、部屋の中のランチパッド（HUD）でページを移らずに行う。

## データ

`user_settings` に 2 列（移行 `0028_home_world`）。行が無い人は既定として扱う。

| 列 | 型 | 既定 | 意味 |
|---|---|---|---|
| `home_world_ref` | text | NULL | ホームのワールドの正規 URL。NULL は公式の既定ワールド（`DEFAULT_HOME_WORLD_REF = 'default'`） |
| `home_access_type` | `instance_access_type` | `invite_only` | ホームの部屋の公開範囲 |

- 既定を招待のみにするのは、ログインのたびに公開一覧へ部屋を出さないため。
- 保存する前にワールドを解決し、正規 URL にそろえる（共有 URL `@handle/name` などを貼られても、部屋の `world_ref` と比べられるように）。開けない URL は 400。
- ホームの部屋を見分ける列（`instances.kind`）は足さない。「自分がリーダー・同じワールドの同じ版・同じ公開範囲」の部屋なら、ワールドの詳細から自分で作った部屋に入っても困らない。

## API（`/api/v1/users`）

| | |
|---|---|
| `GET /me/home` | 設定とホームのワールド（開けなければ `world: null`） |
| `PUT /me/home` | `{worldRef?: string \| null, accessType?}`。省略した項目は変えない。null で既定に戻す |
| `POST /me/home/instance` | ホームの部屋。`?fallback=default` で設定を無視して既定のワールド |

`POST /me/home/instance`（`services/homeInstance.ts`）:

1. 設定のワールドを解決する。開けなければ既定のワールドにして `fallback: 'unresolvable'` を付ける。既定も開けなければ 502。
2. ユーザーごとの advisory lock の中で（タブを 2 つ同時に開いても部屋は 1 つ）、使い回せる部屋を探す（`pickReusableHomeInstance`）。条件はすべて:
   自分がリーダー・同じワールド・同じ版（`content_hash`）・同じ公開範囲・パスワード無し・Go に部屋がある・満員でない・すぐ片付けられない。
3. 無ければ作る。通常のインスタンス作成の上限（IP ごと 10 件/時）には数えず、別に 1 人 10 回/分。

使い回しは「すぐ片付けられない」部屋に限る。空の部屋は `INSTANCE_EMPTY_TIMEOUT_MS`（既定 5 秒）で片付けられるので、余裕は「60 秒と、その半分の短い方」。
つまり使い回すのは、中に人がいる間（切断後の再接続の猶予を含む）とその直後だけで、翌日ログインし直すと新しい部屋になる。

## 画面の流れ

```
/auth  → ログイン → from（既定 /）
/      → HomePage: POST /me/home/instance → /instance/:id（replace）
/instance/:id が失敗 → 5 秒後に / へ（state: { homeFailed: id }）
```

- `HomePage` は待つ間、インスタンスのロード画面と同じ見た目を出す（遷移の継ぎ目を見せない）。
- 失敗の繰り返しを止める: `/` に戻ってきたとき、返ってきた部屋が直前に失敗した部屋と同じなら自動では入らず、「もう一度試す・既定のワールドで入る・ログアウト」を出す（`decideHomeEntry`）。
  同じアカウントで別のタブ・端末から同じ部屋に入ったとき（`session:replaced`）もこれで止まる。
- 既定のワールドに切り替えたときは、入った部屋でトーストで知らせる。
- 共有 URL（`/@handle/name`・`/world/...`・`/instance/:id`）はホームを通らない。

## ランチパッド（`components/hud/HudOverlay.tsx`）

部屋の中の右上（スマホは右下）のボタンで開く。下のドックで画面を切り替える。

| ドック | 中身 |
|---|---|
| ランチパッド | 現在地のバナー（ワールド・人数・公開範囲・ホームの印）、タイル（ワールド・インスタンス・ソーシャル・マイページ・ワールドを作る・ホームの設定）、クイックアクション |
| 通知 | 通知 |
| 現在地 | 今の部屋（入り直し・新しいインスタンス・編集・参加者） |
| 音声 | ワールドのメディア全体の音量・ミュート |
| 設定 | プロフィール・ホーム・ワールド・公開・アカウント・mod の権限 |

クイックアクション:

- **ホーム**: ホームの部屋へ移る。今いる部屋がそれなら閉じるだけ。ほかの人がいるときだけ確認する。
- **リスポーン**: 今の部屋に入り直す（接続・mod・持ち物・乗り物を最初の状態に戻す）。持ち物・乗り物を host が勝手に外すと mod の状態とずれるので、入り直しにした。
- **招待をコピー**: `/instance/:id`。招待のみの部屋はこの URL を渡した人だけが入れる。
- **ログアウト**

ホームに設定する入口は、ワールドの詳細の「ホームに設定」（公開範囲を選んで決める）と、設定の「ホーム」（公開範囲の変更・既定に戻す）。

## 音声

`@ubichill/react` の `mediaOutput`（host 全体で 1 つ）。`<video>` の音量 = mod が `Ubi.media.setVolume()` で決めた音量 × 全体の音量、ミュートは全体で。
mod から見える `state.volume` は mod が決めた値のまま（全体の音量で mod の UI が動かないように）。値は端末の localStorage（`ubichill:media-output`）。

## 未対応・判断待ち

- ロビーをなくしたので、ランチパッドを開かない限り公開インスタンスの一覧が目に入らない。既定のホーム（公式の `default`）にほかの場所への入口を置くかは別に決める。
- 署名の無いワールドをホームにすると、入るたびに入室の確認が出る（確認を飛ばす経路は作らない）。
- ログインしていない人の `/` は今までどおり `/auth` へ。ランディングページは作っていない。
