# ワールド識別と作者署名（URL 非依存の信頼）

対象ブランチ: `feat/world-identity`

## 目的

- ワールドを URL ではなく **中身と作者** で識別する。URL が変わってもデータが同じなら同一と判定できる。
- 作者を暗号学的に確定し、配布元（URL）が乗っ取られても world + lock の偽装を検知できるようにする。
- その識別子を土台に、お気に入りを公開コレクション化し、インスタンス内外で共有する。

## 解決する既知の限界

- lock はワールドと同じ配信元から取るため、配信元を乗っ取られると world + lock を丸ごと差し替えられる（`project_mod_lockfile` 限界 1）。署名が lock hash を含むことで解消する。
- お気に入りタブは local ∪ global 一覧との積で描画しているため、URL 直入室した外部ワールドが表示されない。

## 前提の整理：署名は暗号化ではない

- 署名はワールドを**隠さない**。署名鍵が無くてもワールドは読めるし入れる。鍵が奪われた場合の被害は「その鍵の名義で偽ワールドを作られる」ことであり、既存ワールドの内容が漏れることではない。
- ワールドは公開前提なので機密性は扱わない。

### mod の「盗用防止」について（重要）

- mod は利用者のブラウザ（Worker）で実行されるため、**コードは必ずクライアントに届く**。暗号化しても復号鍵をクライアントに渡す以上、コピーは原理的に防げない（DRM と同じ構造）。
- 署名で防げるのは **なりすまし**：盗んだ mod を再配布されても、原作者の鍵で署名できないので「原作者の mod」を名乗れない。provenance 表示で本物と区別できる。
- 権限 grants を `modId`（自己申告）ではなく `発行者鍵 + modId` をキーにすることで、`id: "pen"` を名乗る偽 mod が過去の許可を引き継ぐ問題（`project_mod_lockfile` 限界 2）も塞ぐ。
- ロジック自体を秘匿したい場合の唯一の手段は、その処理をサーバー側で実行すること（別設計）。

## モデル

### 識別子

| 名前 | 定義 | 役割 |
|---|---|---|
| `contentHash` | `sha256(JCS({ definition, lock }))` | 版の同一性。URL 非依存。改竄検知 |
| `worldId`（署名済みのみ） | `ed25519:<publicKey>/<metadata.name>` | ワールドの同一性。版をまたいで不変 |
| `url` | 最後に取得できた URL | 取得先のヒントにすぎない |

- ハッシュは YAML 生バイトではなく **パース後の JCS（RFC 8785）正規化 JSON**。本体は保存した definition を YAML に再シリアライズして配信するため、生バイトでは一致しない。
- 未署名ワールドは従来通り `url` を識別子にし、UI で「署名なし」と表示する（非公開）。

### 署名ファイル（兄弟ファイル、lock と同じ分離方針）

`<world>.sig.json`（本体ホストのワールドも `GET /api/v1/worlds/:id.sig.json` で同じ形）:

```json
{
  "version": 1,
  "alg": "ed25519",
  "publicKey": "<base64url>",
  "name": "<metadata.name>",
  "contentHash": "sha256-<base64>",
  "signature": "<base64url>"
}
```

署名対象は `{ version, alg, publicKey, name, contentHash }` の JCS。

### 鍵の保持者（サーバーは鍵を持たない）

| 対象 | 鍵 | 備考 |
|---|---|---|
| 本体で作成したワールド | 作者の鍵（ブラウザ生成、IndexedDB に取り出し不可で保存、バックアップファイルはユーザーが保管） | 保存のたびにブラウザが内容に署名し、内容と一緒に `PUT /api/v1/worlds` で送る。サーバーは検証して保存するだけ |
| CLI / GitHub で作るワールド | 公開環境の鍵（`ubichill login`、CI は `ubichill ci create`） | `ubichill publish` で署名する。鍵ファイルを自分で管理する `keygen` / `sign` は廃止（2026-10） |
| `worlds/`（公式） | 公式アカウントの CI 用公開環境（Secret `UBICHILL_CREDENTIALS`） | main に入ったら CI が署名してイメージに同梱する（マージ = 公式としての確認）。署名はコミットしない |
| mod | 作者の鍵（必須方向で検討） | なりすまし防止と grants のキー化 |

- サーバー署名（インスタンス鍵）は採用しない。同じサーバー上では自己保証にしかならず、「検証済み」を誤解させるため。
- DB は信頼の根にしない。秘密鍵も公開鍵の登録も持たず、署名は lock と同じく作者から受け取った配信物として保存するだけ。
- 鍵紛失・ローテーションは初期スコープ外（鍵が変われば別作者扱い）。

### 作者と実在人物の結び付け（後続）

署名で分かるのは「同じ鍵の持ち主」まで。`https://<domain>/.well-known/ubichill.json` に公開鍵を置くドメイン検証を基本とし、GitHub `github.com/<user>.keys` はアダプタの一つとする。

## 層の責務（段階 1 実装済み）

- `@ubichill/shared`: `WorldSignatureSchema` / `WorldIdentitySchema`、`canonicalJson`、`signWorld` / `verifyWorldSignature`。
  暗号プリミティブは `WorldCrypto` / `WorldSigningKey` として注入（shared は Node/DOM 非依存を維持）。
- `@ubichill/loader`: WebCrypto 実装 `webWorldCrypto` / `importSigningKeyPair`（取り出し不可）、CLI の確認 `ubichill verify <world.yaml>`（subpath `verify-world`。署名は `ubichill publish`）。
- backend: node:crypto の検証専用実装（`services/worldCrypto.ts`）。外部ワールドは YAML・lock・sig を並行取得して検証し、
  不正は `WorldIntegrityError`（`/worlds/resolve` は 422、キャッシュへのフォールバック無し）。
  本体ワールドはファイル/DB の生の値を `/api/v1/authors/<handle>/worlds/<name>.yaml` / `.lock.json` / `.sig.json` で配信する。
  保存は `PUT /api/v1/worlds`（内容と署名を一緒に検証して保存）。
  連合ピア一覧の `identity` は自己申告なので捨てる。
- frontend: `lib/signing`（鍵保管・保存時の自動署名）、プロフィールの鍵管理、`WorldIdentityBadge`（作者署名あり / 署名なし）。

## 表示と意味

- バッジは「作者署名あり」/「署名なし」。「検証済み」とは呼ばない。署名が保証するのは
  「その鍵の持ち主が作り、改竄されていない」ことだけで、鍵は誰でも作れるため安全性の保証ではない。
  安全性は sandbox + capability 天井 + lock が担う。

## 鍵の置き場所

| 使い方 | 場所 |
|---|---|
| ブラウザ | そのサイト（オリジン）の IndexedDB。サイトごとに分かれるので、別サーバーでは同じバックアップを読み込む |
| CLI | `~/.config/ubichill/credentials.json`（`ubichill login` が作る。0600）。CI は Secret `UBICHILL_CREDENTIALS` |
| 公式ワールド | CI の Secret `UBICHILL_CREDENTIALS`（公式アカウントの CI 用公開環境） |

署名はワールドの内容に対するもので、サーバーや URL には依存しない。どのサーバーでも検証できる。
ただし本体で作ったワールドは保存時にサーバーが `metadata.name` を採番するため、別サーバーに持っていくと
`worldId`（公開鍵 + name）は変わる。

## 作者アカウント（handle@domain）

- ユーザーは **表示名**（`users.name`、日本語可・**一意**・変更可、VRChat と同じ）と **ID**（`users.handle`、英小文字・数字・_ の 3〜30 文字、一意、変更不可）を持つ。
  表示名の一意性は `displayNameKey`（NFKC・空白圧縮・小文字化）で判定し、全角半角・大文字小文字・空白の違いを同じ名前とみなす。
  移行時に重複していた既存ユーザーはキー未設定にし、プロフィールで変更を促す。
  ID は URL・署名などの機械用。旧 `username` は表示名と重複していたため非推奨（既存値が規則を満たす人は handle に引き継ぎ）。
- 作者アカウントは `handle@domain`（表示は `@youkan@ubichill.com`）。domain は PUBLIC_BASE_URL のホスト。
- **1 アカウントに複数の鍵（公開環境ごとに 1 本）**（2026-09-29、`docs/design/author-publishing.md`）。`publishing_environments` に
  公開鍵だけを保存（秘密鍵はブラウザ・CLI・CI の手元）。登録時は userId・公開鍵・時刻を含む文にその鍵で署名させ、所有を証明させる
  （他人の公開鍵を自分に登録して他人の作品を奪えないように）。取り消しは削除せず `revoked_at` を立て、取り消した鍵は二度と登録できない。
- 署名は `author` を含められる（署名対象）。検証側は `https://<domain>/.well-known/webfinger?resource=acct:handle@domain`
  （RFC 7033、自サーバーなら DB）の links（rel `https://ubichill.com/ns/signing-keys`）から鍵一覧を辿り、署名鍵が**取り消されていない**
  鍵のときだけ作者として表示し、worldId を `acct:handle@domain/name` にする。
  そうでなければ作者を付けず鍵で識別する（なりすましを表示しない。署名自体は有効なので invalid にはしない）。
- 保存時、署名の `author` がアップロードした本人のアカウントでなければ 422。
- **表示名はワールドのデータに持たせない**。サーバーは作成時に `metadata.author` へ表示名を書かず、本体で作ったワールドの
  作者名は表示時に authorId からその時点の表示名を引く。`metadata` は署名対象なので、表示名を書き込むと改名のたびに
  全ワールドの署名し直しが必要になるため。外部ワールドの作者名も、署名で確認できた作者アカウントのサーバーの WebFinger（`https://ubichill.com/ns/display-name`）
  からその時点の表示名を引く。作者アカウントを確認できないワールドには作者名を表示しない（`metadata.author` の自己申告は使わない）。
- **作者の表示は署名で確認できた `author` だけを使う**。`metadata.author` は作者の自己申告（鍵の持ち主が書いた任意の文字列）で、
  どのサーバーが保証したかを表さないため、`@handle@domain` を書いても信頼の根拠にしない。UI は `@handle` と `@domain` を分けて
  表示し、どのサーバーがその作者の鍵を証明しているかを見せる。
- 公開環境を取り消すと、その鍵の署名は**取り消し前のものも含めて**作者表示が外れ、一覧に出なくなる（現役の環境で署名し直すと戻る）。
- **信頼**: 「この鍵は youkan のもの」はドメイン（サーバー運営者）が保証する。改竄検知は暗号で保証。
  自分のドメインで WebFinger を公開すれば特定サーバーに依存しない（検証側は任意ドメインに対応済み、発行 UI は未対応）。

## 公開の一本化（2026-10-03 決定）

本体の DB に置くワールド・リポジトリ（`worlds/`）のワールド・外部ホストのワールドを、**同じ形・同じ規則・同じ方法**で公開する。
配信場所による特別扱いはしない。

- **形は 1 つ**: どのワールドも「world 定義・lock・署名」の組（`WorldBundle`）。検証は `resolveBundle` の 1 経路で、
  署名が壊れていれば配信場所に関係なく拒否する（以前は本体のワールドだけ未署名に格下げしていた）。
- **ホストは中身を書き換えない**（`metadata.name` も）。同じワールドかは「作者 + `metadata.name`」で決まり（外部と同じ）、
  DB には `world_name` 列（作者ごとに一意）を持つ。内部の ID（`worlds.name`）はエディタ・API 用で、公開の URL には出さない。
  これにより prepare（サーバーが保存する値を先に受け取って署名する手順）と CLI の `<world>.ubichill.json` は不要になった。
- **URL は作者と名前**: 共有 URL は `/@handle/name`、配信の正規 URL は `/api/v1/authors/handle/worlds/name.yaml`。
  共有 URL から文字列だけで正規 URL が決まるので、ほかのサーバーも DB なしでたどれる。保存（下書きを含む）には ID が要る。
  - **名前の変更は移動**: `metadata.name` を変えて保存すると、同じワールドのまま URL が変わる（GitHub のリポジトリ名の変更と同じ）。
    以前の名前は `world_name_aliases` に残し、以前の URL（お気に入り・インスタンス・共有したリンク）からも同じワールドをたどれる。
    以前の名前で新しいワールドを作ると、そちらが優先される。署名は名前を含むので、公開中のワールドは公開し直したときに名前が変わる
    （下書きでは変わらない）。自分の別のワールドと同じ名前にすると上書きせず 409。
  - 以前の形（`/world/<id>`、`/api/v1/worlds/<id>`）は自ホストなら内部 ID で解決し、画面は `/@handle/name` へ移す。
    保存済みの参照（お気に入り・インスタンス）は移行 0013 で正規 URL に書き換える。
- **本体へ送る入口は 1 つ**: `PUT /api/v1/worlds`（`{ yaml, lock, signature? }`）。新規・更新・下書き・署名し直しはすべてこれ。
  署名ありは外部と同じ規則で検証して公開中の版として保存（下書きは消す。ただし公開中の版と同じ内容への署名し直しでは残す）。
  署名なしは、公開中のワールドなら公開中の版を残して下書きに、そうでなければ署名なしで保存（公開されない）。
  署名には作者アカウントが要る（作者の付かない署名は公開されないので保存の時点で拒否する）。
- **配り方も 1 つ**: 本体のワールド（DB・リポジトリとも）は `/api/v1/authors/<handle>/worlds/<name>.yaml` と兄弟の
  `.lock.json` / `.sig.json`（CORS `*`）。GitHub Pages などの外部ホストと同じ形で、受け取る側の兄弟 URL の規則も 1 つ（拡張子の置き換え）。
  リポジトリのワールドは置いてあるファイルをそのまま返し、DB のワールドは公開中の版をファイルにして返す（下書きは配らない）。
  以前の配信の形（`/api/v1/worlds/<id>` の YAML 応答・`/yaml`・`/lock`・`/sig`）は廃止。
- **ほかのサーバーの作者のワールドは写しを配らない**: リポジトリ（`worlds/`）のワールドは、作者がこのサーバーのアカウントのものだけ配る
  （ubichill.com なら公式ワールド）。プレビューや自前のサーバーは、公式ワールドの写しを抱えず、公式アカウント（管理者）が
  設定の「連合」で https://ubichill.com をフォローして参照する。`WORLDS_REGISTRY_URLS`（使われていなかった）と
  レジストリの列挙は廃止し、ワールドの一覧への取り込みは連合だけにした。作者の確認は署名が名乗る作者のドメインを先に見て、
  ほかのサーバーなら検証もしない（一覧のたびに問い合わせない）。
  - 制約: 連合は相手のサーバーもこの形で配る版である必要がある。ubichill.com が更新されるまで、ほかのインスタンスの
    「グローバル」に公式ワールドは出ない。プレビューで公式ワールドやその mod の変更を試すときは、プレビューの URL を指定して
    プレビューのアカウントで公開し直す（`ubichill publish --server=https://pr-N.ubichill.com`。作者は別になる）。
    初期のフォロー先は env `WORLDS_FEDERATION_PEERS`（カンマ区切り）でも入れられる（プレビューを作り直すたびにフォローし直さない）。
- **公式ワールドの署名は CI**: ほかの作者の CI と同じ方法。main に入ったら CI が公式アカウントの CI 用公開環境
  （Secret `UBICHILL_CREDENTIALS`、`ubichill ci create` で作る）で `ubichill publish worlds/*.yaml --out=worlds` してイメージに同梱する。
  マージ = 公式としての確認。署名はリポジトリに置かず、メンテナの鍵ファイル（`official-worlds.key`・`pnpm sign:worlds`）は廃止。
  プレビューのイメージには署名しない。GitHub が乗っ取られると公式名義で署名されるので、Secret と main の保護を絞ること。
- **特別な信用はしない**: `worlds/trusted-authors.json` を廃止した。公式アカウント（`ubichill@ubichill.com`）の鍵も、
  ほかの作者と同じく ubichill.com の公開環境で、WebFinger で確かめる。画面からの取り消しも同じく効く。
- **lock は常に必須**: 配信場所・署名の有無に関係なく、lock に固定されていない mod は実行しない（`strictLock` / `isStrictLockWorld` を廃止）。

## mod 固定の徹底（2026-09-27）

- **作者署名が有効なのは、ワールドが実行し得る全 mod が lock に固定されているときだけ**。
  対象は初期エンティティの mod と `dependencies` の和集合（dependencies だけの mod も実行中に生成され得る）。
  固定されていない・定義を解釈できない署名は `lock-incomplete` で無効（保存 422、外部解決は拒否）。
  → 「作者署名あり ⇒ 全 mod のコードが署名時のバイト列に固定」が常に成り立つ。
- 実行時は常に厳格（lock 欠落・不一致の mod を実行しない。2026-10-03 に配信場所による寛容を廃止）。
- lock の生成（`ubichill install`・エディタ保存）も dependencies を含める。固定できない mod があれば
  CLI は署名せず理由を表示し、エディタは「このままでは公開できません」と対象 mod を示す。

## 下書きと公開（2026-09-28）

- エディタの操作は「公開する」（主）と「下書き保存」（副）。下書き保存は鍵・ID などの準備が一切不要。
- 公開中（署名済み）のワールドを下書き保存しても公開中の版と署名は変わらず、下書きは `worlds.draft_definition` / `draft_lock`
  に別に保存される。公開すると下書きを本体へ反映して消す。未署名のワールドは下書きを本体に直接保存する（URL から試しに入れる）。
- 公開の準備ダイアログには「非公開で保存」を置かない（押したくなる位置に非公開の出口を置かない）。

## 初回公開の導線（2026-09-29 改訂）

- ログインできる = 公開できる。「公開する」を押すと、このブラウザに鍵が無ければ作り、公開環境として自動で登録して署名する（確認は出さない）。
  利用者に求めるのは ID（未設定のときだけ、その場で決める）。鍵ファイルのダウンロードはしない（端末ごとに公開環境を持つ）。
- このブラウザの鍵が取り消し済みなら、捨てて新しい鍵を作り直す。
- 設定の「公開」（公開できるブラウザ・CLI・CI）で一覧・取り消しができる。長く使われていない環境は目立たせる。
  CLI の鍵ファイルの読み込みは上級者向けに残す。
- 既存の未署名ワールドは、ロビーに「N 個が一覧に表示されていない → 署名して公開」を出して移行を案内する。

## 公式アカウントと管理者（2026-09-28）

- 公式アカウント（ID `ubichill`）はサーバー起動時に用意する。公式ワールドの作者とこのサーバーの管理者を兼ねる
  （`admin@...` のような別の管理者アカウントは作らない）。
- ログイン用メールは env `OFFICIAL_ACCOUNT_EMAIL`（既定 `ubichill@ubichill.com`）。パスワードは env
  `OFFICIAL_ACCOUNT_PASSWORD`（Helm の `backend.secretEnv`）が**常に正**で、起動のたびに合わせる（2026-09-28 決定）。
  変更は Secret を差し替えて再デプロイするだけで、値が変わったときだけ既存のログインを無効にする。
  画面からも better-auth の `/change-password` からも変更できない（変えても次の起動で戻るため受け付けない）。
  開発環境で未設定なら公開済みの既定値を使い、設定を促す表示を出す。本番で未設定なら作成も同期もしない（警告のみ）。
  Secret を読める人は管理者兼公式の作者になれるので、Secret を読める人を絞ること。
  管理者の操作はクッキーキャッシュ（最大 5 分）を使わず DB のセッションを確かめるので、Secret の差し替え直後から
  古いログインでは管理者の操作ができない。管理者以外の操作は、キャッシュが切れるまで最大 5 分通る。
- 署名の鍵はほかの作者と同じく公開環境（`ubichill login` など）で登録する。リポジトリの記録で特別に信用しない（2026-10-03）。
- 管理者だけが、連合ピアの追加・削除、ワールドの再読み込み・並べ替えを実行できる（以前はログインしていれば誰でも実行できた）。
- 管理者の権限と公式名義での公開が 1 つのアカウントに集まるので、アカウントの安全性（#184）を優先して進める。

## 公開ルール: 作者アカウント必須（2026-09-27 決定・例外なし）

- 公開できるのは、署名が有効で**作者アカウント（どこかのサーバーに実在する handle@domain）まで確認できた**ワールドだけ。
  鍵だけの署名（作者不明）・未署名は一覧に出さず、URL からの入室時に確認する。作者名もアカウントから引き、自己申告は使わない。
- 公式ワールドも例外ではなく、作者 `ubichill@ubichill.com` で署名する（main の CI が署名する）。
- **確認結果の保存と期限**: 他サーバーの作者アカウントの鍵一覧と表示名は `author_bindings` に保存し、通常アクセスはそれを使う。
  T_fresh（1 時間）を超えたら保存した結果で即答して裏で取り直し、知らない鍵（新しい公開環境）の署名が来たときだけ待って取り直す。
  取り消しは鍵一覧の `revokedAt` で届く。取り直せない（作者のサーバーが止まっている）間は最後の結果を T_max（14 日）まで使い、
  確認から 24 時間を超えたら「確認が古い」と表示し、それまでに確認済みだった内容にだけ作者を付ける。取り消しが届くのは
  「T_fresh ＋ 5 分、かつアクセスがあった後」（詳細と信頼モデルは `author-publishing.md`）。
- 公式ワールドにも特別な信用はない（`worlds/trusted-authors.json` は 2026-10-03 に廃止）。CI の `verify:world-locks` は
  lock だけを検証し、署名は main の CI が付ける。鍵が公開環境にあるかは配信先のサーバーが確かめる。
- 署名済みワールドを黙って未署名にしない保護は、作者確認の有無に関係なく署名が有効なら働く。

## 公開ルール（2026-09-26 決定・上で強化）

- 署名検証済み（`isPublishable`）だけを一覧・連合一覧・プロフィール・インスタンス一覧に出す。
- 未署名は URL を知っていれば入れるが、`/instance/:id` で入室前に確認する（全入口が通る 1 箇所。
  セッション内で許可済みでも contentHash が変われば再確認）。インスタンス情報を取得できなければ
  署名の有無を確認できないので参加しない（確認を飛ばさない）。
- 連合ピアの一覧は自己申告を捨て、各ワールドを取得・検証して verified だけ残す。

## 勝手に未署名にならないための防御

| 経路 | 対策 |
|---|---|
| エディタ保存（鍵なし） | 公開中のワールドなら下書きになり、公開中の版と署名は変わらない |
| エディタ保存（鍵あり・署名失敗） | 手元で署名して内容と署名を 1 回の PUT で送る。署名が通らなければ何も保存しない |
| 新規作成 | 作成と署名も同じ 1 回の PUT（サーバーが中身を書き換えないので、送る前に署名できる） |
| 他クライアント・API 直叩き | 同じ PUT しかない。署名なしで送れば公開中のワールドは下書きになるだけ |
| 起動時の DB マイグレーション | 署名済みレコードは書き換えない（読み出し時に同じ変換が掛かる） |
| 公式ワールドの lock 再生成 | CI が無効な署名を検出してマージを止める |
| 配信元の乗っ取りで sig を削除 | 未署名になるので一覧から消え、入室時に確認が出る（既知 worldId との照合は段階 2） |

## 既知の限界

- **ワールドの参照は URL（2026-09-27 決定）**: お気に入り・インスタンスは URL で参照し、URL が変わったら別のワールドとして扱う。
  worldId は計算するが、現時点では利用体験（お気に入りの追従・取り込み時の同一性維持）には使わない。

- **未署名への格下げ**: 配信元を乗っ取った攻撃者は sig を消せば unsigned にできる。既知 `worldId` との照合
  （お気に入りに verified で登録済みなのに unsigned / 別鍵で返ってきたら警告）は段階 2 で入れる。
- **兄弟 lock の取得失敗**: 一時的な取得失敗でも lock=null として hash が合わず拒否される（fail closed）。
- **鍵はブラウザ単位**: 別端末ではバックアップファイルの読み込みが必要。読み込まずに新しい鍵を作ると別作者になる。
- **XSS 下での悪用**: 鍵は持ち出せないが、ページを開いている間に任意の内容へ署名させることはできる。
- **既存ワールドは非公開になる**: 導入前に作られたユーザーワールドは未署名なので、作者が鍵を用意して保存し直すまで一覧から消える。
- **公式ワールドの更新はメンテナ鍵の保持者だけ**: mod を変えて lock が変わると、鍵を持つ人が署名し直すまで CI が通らない。
  鍵は ubichill.com の公式アカウントの公開環境にあること（無ければ配信先で作者が付かず一覧に出ない）。
- **連合一覧の取得コスト**: ピアの各ワールドを取得・検証する（5 分キャッシュ）。ピアが大量のワールドを持つと重い。
- 作者と実在人物の結び付け・鍵ローテーション・アセットの hash 固定は未対応。
