# サーバーの紹介とサーバーの情報

ログインしていない人が `/` を開くと、サーバーの紹介のページを出す。サーバーの名前と紹介、新規登録とログインの入り口、このサーバーのワールド、運営の情報を並べる（Misskey の入口のページにならった）。中身は管理者がコントロールパネルの「全般」で設定する。ログインの画面は別に持たず、この上のダイアログで開く（前の `/auth` は `/` へ移す）。

## できること

- コントロールパネルの「全般」で、次のものを設定する。どれも公開する（紹介のページ・NodeInfo）。
  - サーバー名（必須）、サーバーの紹介
  - 管理者の名前とメールアドレス
  - 利用規約・プライバシーポリシー・問い合わせ先・ソースコード・運営者情報（Impressum）の URL
- 紹介のページ（`pages/VisitorPage.tsx`）
  - サーバー名と紹介（書いていなければ Ubichill の紹介）、「新規登録」（受け付けているときだけ）と「ログイン」
  - Mastodon・Misskey のアカウントでのログイン・登録（コントロールパネルの「認証」で決めたサーバーと「その他のサーバー」）。押さずに見えるよう、最初から並べる
  - 人数（システムのアカウントを除く）とワールドの数、このサーバーのワールド（12 件まで）。情報を読めなかったときは、人数と「新規登録」を出さない
  - 管理者と、入れた URL。ソースコードは、書いていなければ Ubichill のリポジトリを出す（AGPL）
- ログイン・新規登録のダイアログ（`pages/VisitorPage.tsx`・`components/auth/PasswordAuthForm.tsx`）
  - 「新規登録」「ログイン」で、メールアドレス（ログインでは ID も）とパスワードの形を開く。開いているものは URL のクエリに残す（`?mode=login`・`?mode=register`。読み込み直しても同じものを開く）。中の文字でログインと登録を替える（替えたら最初の欄へフォーカスを移す）。
  - 続きもこのダイアログで出す: ログインの二段階目（`?two_factor=1`）、フェディバースのアカウントで初めて来た人が ID と表示名を決める（`?fediverse=sign-up`）。
  - Esc・外側・右上のボタンで閉じる。開いたら最初の欄へ、閉じたら開いたボタンへフォーカスを移す。開いている間、後ろのページは操作できない（`inert`）。フェディバースでの登録を閉じたら、登録の途中の状態を消す。
  - 新規登録を止めているサーバーでは、登録への切り替えを出さず、`?mode=register` もログインにする。
- ログインが要る画面から来たときは `/?next=<戻り先>` にする（`ProtectedRoute`・ワールドのページ・CLI の承認など）。ダイアログは自分では開かない。ログインしたら戻り先へ移る（ログインしたまま開いても移る）。
- 前の `/auth` へのリンク・ブックマークは、クエリをそのまま `/` へ移す（`?add=1`・`?two_factor=1` なども同じ意味で読む）。
- 新規登録を終えたら（認証コードを確かめたら）、そのままログインする。

## 決めたこと

| 決めたこと | 理由 |
| --- | --- |
| ログインしていない人の `/` は紹介のページにする | どんなサーバーかが分かってから登録してもらう。ログインしている人は今までどおりホームの部屋へ入る。 |
| ログインの画面（`/auth`）をやめ、`/` の上のダイアログにする | 入り口が 2 つあると、どちらが正しいか分からない。紹介を見ながら、そのままログイン・登録できる。 |
| Mastodon・Misskey のアカウントでの入り口は、ダイアログに入れずページに最初から並べる | 押してから選ばせるより、使える方法がすぐ分かる。ダイアログの中はメールアドレスとパスワードだけにして短くする。 |
| ページから始めるフェディバースのログインは、ログインとして始める（`prefer: 'sign-in'`） | ログインか登録かを選ばせない。多いのは登録済みの人なので、そのままログインする。まだ登録されていない人には「まだ登録されていません。ID と表示名を決めると、このまま登録できます」と出る。 |
| `?next=` で来たときはダイアログを開かない | ページの SSO も見えるようにする（メールアドレスで入る人だけのためにダイアログで隠さない）。 |
| 外側を押して閉じるのは、押し始めも外側だったときだけ | 欄の文字を選んで外で離したときに閉じない。 |
| 紹介のページの左の列を、画面に貼り付けない（sticky をやめた） | フェディバースのサーバーを並べて縦に長くなり、画面より長いと下が見えなくなる。 |
| ログインしているか確かめられない（get-session が一時的に失敗）とき、`/` は読み込み中にする。ただし `?next=`・ダイアログ・アカウントの追加で来たときは紹介のページを出す | ログインしている人に紹介のページを一瞬見せない。ログアウトした直後の失敗では、ログインし直せるようにする。 |
| ダイアログを開いている間は、版のずれで勝手に読み込み直さない | 入れている途中のパスワードや認証コードが消える。 |
| ログインの画面は ID とパスワードを一緒に入れる（Misskey のように ID を先に入れて、アイコンと「おかえりなさい」を出す形にしない） | ID だけ先に入れさせると、メールアドレスで入れた人には、そのアドレスのアカウントがあるかが分かってしまう。パスワードの管理ツールでも一度に埋まる。 |
| 登録のメールアドレスの欄は `autocomplete="username"` | パスワードの管理ツールに、メールアドレスをアカウントの名前として覚えさせる（ログインの欄と同じ値で埋まる）。 |
| 登録を終えたらそのままログインする | 登録した直後にもう一度パスワードを打たせない。本登録できるのは、パスワードを決めて申し込んだブラウザー（仮登録の ID はそこにしか返さない）で、メールの認証コードも入れた人だけなので、パスワードのログインと同じ扱い（パスワードを確かめた時刻付き）のセッションを作る。認証コードは再送で期限が延びるので、パスワードを入れてから時間が経っていることはある。 |
| 略称・バナー画像・アイコンの差し替えは入れていない | 使う場所がまだ無い（略称）・画像の置き場を決めていない。要るときに足す。 |

## 仕組み

### サーバーの情報

- `server_info`（1 行だけ。無ければ既定の値。migration 0044）。値の規則は shared の `ServerInfoSchema`（URL は http(s) だけ、空の欄は null）。
- `GET /api/v1/server`: 紹介のページに出すもの（情報・新規登録を受け付けているか・人数）。管理者が変えたらすぐ出るよう `no-cache`（変わっていなければ 304）。
- `GET`・`PUT /api/v1/admin/server-info`: コントロールパネル（管理者だけ）。
- NodeInfo（`/nodeinfo/2.1`）の `metadata` に、Misskey・Mastodon が読む名前（`nodeName`・`nodeDescription`・`maintainer`・`tosUrl` など）で入れる。`openRegistrations` も設定に合わせた（前は常に true）。読めないときも、サーバーの判別（ソフトと連合の版）はできるよう情報を除いて返す。

### 登録の後のログイン

- 本登録（`POST /api/v1/users/verify`。メール確認を飛ばす開発環境では `POST /api/v1/users/register`）の後、サーバーの中から better-auth の口（`lib/registrationSignInPlugin.ts`、`/registration/sign-in`）を呼んでセッションを作り、そのクッキーを応答に付ける。
- この口は HTTP からは呼べない（`SERVER_ONLY`。`lib/authEndpoints.ts` の許可リストにも入れない）。
- セッションはパスワードのログインと同じ作り方（`signInOrChallenge`）。登録したばかりの人は二段階認証を使っていないので、そのままセッションになる。このブラウザーでログインしているほかのアカウントは残る（アカウントの追加の途中で登録した場合）。
- セッションを作れなかったときは、登録はできたと返し、画面が「ログインしてください」と出す。

## 残り

- 紹介のページの OGP（`packages/bff`）にサーバー名と紹介を入れる。
- サーバーのアイコン・バナー画像を差し替えられるようにする。
