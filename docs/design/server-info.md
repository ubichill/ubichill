# サーバーの紹介とサーバーの情報

ログインしていない人が `/` を開くと、サーバーの紹介のページを出す。サーバーの名前と紹介、新規登録とログインの入り口、このサーバーのワールド、運営の情報を並べる（Misskey の入口のページにならった）。中身は管理者がコントロールパネルの「全般」で設定する。

## できること

- コントロールパネルの「全般」で、次のものを設定する。どれも公開する（紹介のページ・ログインの画面・NodeInfo）。
  - サーバー名（必須）、サーバーの紹介
  - 管理者の名前とメールアドレス
  - 利用規約・プライバシーポリシー・問い合わせ先・ソースコード・運営者情報（Impressum）の URL
- 紹介のページ（`pages/VisitorPage.tsx`）
  - サーバー名と紹介（書いていなければ Ubichill の紹介）、「新規登録」（受け付けているときだけ）と「ログイン」
  - 人数（システムのアカウントを除く）とワールドの数、このサーバーのワールド（12 件まで）。情報を読めなかったときは、人数と「新規登録」を出さない
  - 管理者と、入れた URL。ソースコードは、書いていなければ Ubichill のリポジトリを出す（AGPL）
- ログインの画面（`/auth`）
  - タブをやめた。紹介のページから「新規登録」で来ると `?mode=register` で登録の形を開き、画面の下の文字で替える（替えたら最初の欄へフォーカスを移す。form の名前で今の形が分かる）。
  - 新規登録を止めているサーバーでは、登録への切り替えを出さず、`?mode=register` もログインの形にする。
  - 見出しはサーバー名。アイコンから紹介のページへ戻る。
- 新規登録を終えたら（認証コードを確かめたら）、そのままログインする。

## 決めたこと

| 決めたこと | 理由 |
| --- | --- |
| ログインしていない人の `/` は紹介のページにする（`/auth` へ飛ばさない） | どんなサーバーかが分かってから登録してもらう。ログインしている人は今までどおりホームの部屋へ入る。 |
| ログインの画面は ID とパスワードを一緒に入れる（Misskey のように ID を先に入れて、アイコンと「おかえりなさい」を出す形にしない） | ID だけ先に入れさせると、メールアドレスで入れた人には、そのアドレスのアカウントがあるかが分かってしまう。パスワードの管理ツールでも一度に埋まる。 |
| 登録のメールアドレスの欄は `autocomplete="username"` | パスワードの管理ツールに、メールアドレスをアカウントの名前として覚えさせる（ログインの欄と同じ値で埋まる）。 |
| 登録を終えたらそのままログインする | 登録した直後にもう一度パスワードを打たせない。本登録できるのは、パスワードを決めて申し込んだブラウザー（仮登録の ID はそこにしか返さない）で、メールの認証コードも入れた人だけなので、パスワードのログインと同じ扱い（パスワードを確かめた時刻付き）のセッションを作る。認証コードは再送で期限が延びるので、パスワードを入れてから時間が経っていることはある。 |
| 略称・バナー画像・アイコンの差し替えは入れていない | 使う場所がまだ無い（略称）・画像の置き場を決めていない。要るときに足す。 |

## 仕組み

### サーバーの情報

- `server_info`（1 行だけ。無ければ既定の値。migration 0044）。値の規則は shared の `ServerInfoSchema`（URL は http(s) だけ、空の欄は null）。
- `GET /api/v1/server`: 紹介のページに出すもの（情報・新規登録を受け付けているか・人数）。管理者が変えたらすぐ出るよう `no-cache`（変わっていなければ 304）。
- `GET`・`PUT /api/v1/admin/server-info`: コントロールパネル（管理者だけ）。
- NodeInfo（`/nodeinfo/2.1`）の `metadata` に、Misskey・Mastodon が読む名前（`nodeName`・`nodeDescription`・`maintainer`・`tosUrl` など）で入れる。`openRegistrations` も設定に合わせた（前は常に true）。読めないときも、サーバーの判別（ソフトと連合の版）はできるよう情報を除いて返す。

### 登録の後のログイン

- 本登録（`POST /api/v1/users/verify`。メール確認を飛ばす開発環境では `POST /api/v1/users/register`）の後、サーバーの中から better-auth の口（`lib/registrationSignInPlugin.ts`、`/registration/sign-in`）を呼んでセッションを作り、そのクッキーを応答に付ける。
- この口は HTTP からは呼べない（`SERVER_ONLY`。`lib/authEndpoints.ts` の許可リストにも入れない）。
- セッションはパスワードのログインと同じ作り方（`signInOrChallenge`）。登録したばかりの人は二段階認証を使っていないので、そのままセッションになる。このブラウザーでログインしているほかのアカウントは残る（アカウントの追加の途中で登録した場合）。
- セッションを作れなかったときは、登録はできたと返し、画面が「ログインしてください」と出す。

## 残り

- 紹介のページの OGP（`packages/bff`）にサーバー名と紹介を入れる。
- サーバーのアイコン・バナー画像を差し替えられるようにする。
