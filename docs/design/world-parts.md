# mod なしで置けるワールドの部品と画像

mod を書けない人でもワールドを作れるようにする最初の段。本体の部品（イメージ・テキスト・ポータル）と、画像を上げる場所、背景の画像を足す。形式は [ワールド定義フォーマット](../worlds/FORMAT.md) を参照。

## 段階

1. **（この段）部品と画像**: `core:image`・`core:text`・`core:portal`、画像のアップロード、背景の画像。エディタの設定欄は部品の宣言から作られるので、足した時点でエディタで使える。
2. **動きの部品とプレハブ**: スポーン・ワープ・スイッチ・音、ブラウザでプレハブを作って配る道、Ubichill Home の作り直し。[mod を書かずにワールドを組み立てる](world-building.md) を参照。

## 決めたこと

| 決めたこと | 理由 |
| --- | --- |
| 部品は本体（`core:*`）に置く | mod にすると、使うたびに依存と lock と署名が要る。イメージ・テキスト・ポータルはどのワールドでも使う基本の部品なので、Host が持つ。 |
| 画像は Postgres に置く（プロフィール画像と同じ） | オブジェクトストレージが無く、backend が複数台ある。送られた画像は作り直す（向きを直し、位置情報などのメタデータを消し、長い辺を 2048px に縮めた WebP）。WebP は非可逆（quality 82）で、PNG・GIF は縮めた後が 256 色以下なら可逆も作って小さい方を取る（ドット絵・色の少ない絵は可逆の方が小さく、縁がにじまない。色の多いスクリーンショット・写真は可逆が 2〜10 倍になるので作らない。可逆が失敗するか 1 秒を越えたら非可逆を使う）。AVIF は URL（`.webp`）が変わり、作るのが重いので使わない。 |
| URL は中身のハッシュ（`/api/v1/assets/<hash>.webp`） | 同じ URL の中身が変わらないので長く cache でき、署名したワールドが指す画像も変わらない。同じ画像はだれが上げても同じ URL。 |
| 1 人あたりの合計に上限を掛ける（既定 200 MB。管理者がコントロールパネルの「全般」で 10 MB〜10 GB に変える） | DB に置くので上限を掛ける。同じ人の同時のアップロードでも越えないよう、持ち主ごとに順番に数える。数（以前の 200 枚）は数えない（合計を 1 GB に上げても、数の上限が先に効いて意味がなくなるため）。下げても置いてある画像は消さない（越えている人は、減らすまで新しく上げられない）。 |
| どのワールドにも使われない画像は、上げてから 7 日で消す | 撮り直したサムネイル・差し替えた画像が残り続け、サーバーと本人の上限を埋める。7 日は、上げてまだ保存していない画像を守る（上げ直すと数え直す）。見るのはこのサーバーのワールドの下書き・版（だれのものでも）だけなので、ほかのサーバーや GitHub Pages のワールドだけが使う画像も消える。消したワールドだけが使っていた画像は次の掃除で消える（同じ画像を上げ直せば同じ URL が戻る）。本人は設定の「ストレージ」で止められる（ほかのサーバーのワールドで使っている人向け。止めた人の画像は掃除が読み飛ばす）。 |
| 画像はだれでも読める | ほかのサーバーで開いたワールドからも読む（CORP は cross-origin）。直接開かれても文書として何も実行させない（CSP の sandbox・nosniff）。 |
| ポータルは、行き先のワールドのページへ移す（部屋に直接入れない） | ワールドのページは、今ある部屋に入るか新しく作るかを選べる。人のいる部屋に入れるようにする。移る前に確かめ、今の部屋から出る。 |
| ポータルの行き先は `@ID/名前`・ワールドの ID・ワールドの URL | ワールドのページを開ける書き方だけを通す（`javascript:` などは検証で落とす）。 |
| 文字の色・大きさは schema で `#RRGGBB`・数値に限る | 作者の値を style に入れるので、CSS を差し込ませない。背景の画像の URL も URL として正規化してから CSS に入れる。 |
| 背景の画像は既定値を持たない | 足す前のワールドの解釈（と既定値で埋めた値）を変えない。 |
| UI は四角（塗り・枠線・角丸・テキスト）で、ボタンにすると同じ Entity のスクリプト（ワープ・スイッチ・ポータル）を動かす。ボタンにした UI が無ければスクリプトは標準のボタンを出す | 動きと見た目を分ける（FigJam の図形に動きを割り当てる形）。見た目を変えたいときだけ UI を足せばよく、置いてすぐ押せる。部品ごとに「見た目なし」の項目を持たせると、同じことを 3 か所で決めることになる。 |
| 1 つのボタンで動くポータルは最初の 1 つだけ。ワープ・スイッチを並び順に動かしてから、最後にポータルを動かす | ポータルが 2 つ動くと確かめる画面が重なり、後の行き先が先の確認を上書きする（確かめた人が見ていない行き先へ移る）。部屋を出た後のワープ・スイッチは意味がないので先に済ませる。 |
| 確かめる画面は一度に 1 つで、後から来た確認が前の確認を「やめた」で閉じて出る | 先の確認を残して後を断ると、開発時の StrictMode で入室の確認が 2 回来たときに入れなくなり、戻る操作の後も前の画面の確認が残る。前の確認は答えを返して終わらせる（待ったまま残さない）。1 回押して移る先は 1 つ（上）なので、行き先が重なることはない。 |
| ボタンを押した動きが終わるまで、同じボタンは押し直しても動かない | 確かめる画面が出ている間、ボタンにフォーカスが残る。Enter を押し直すとスイッチが部屋の全員の画面で切り替わり直す。 |
| エディタの欄の既定値は、data に無いときに部屋で描く値（schema の既定値）。置いたときの見た目（白い角丸の四角にテキスト）は、足したときの data に書く（`defaultData`） | 欄の既定値を置いたときの見た目にすると、YAML で書いた UI（`button: true` だけなど）の欄に、描いていない白・角丸が出る。 |
| ボタンにした UI の HTML は見た目だけ（`inert`） | 中のリンクを押すと、リンクとボタンのどちらが動くか決まらない。ボタンの中に押せるものを入れない。 |
| `requires.protocol` は上げない | これは mod の Host ⇔ Worker の版。新しい部品を使ったワールドは、古い版のサーバーでは定義の検査で断られる（読む側を新しくするまで開けない）。 |

## 仕組み

- 部品の data の形は `packages/core-components/src/{image,text,portal}`。描くのは `packages/frontend/src/world/Core{ImageSurface,TextSign,Portal}.tsx`（置き場所は `surfacePlacement` で `core:ui` と同じ）。
- UI のボタンは同じ Entity のスクリプトを動かす（`world/entityButton.ts` の `entityScripts` で探し、`planButtonPress` で順番と動かすものを決め、`useScriptRunner` で動かす。標準のボタンも同じ動かし方を使う）。動かないポータルは `idleButtonScripts` で引き、エディタの Component の欄に知らせを出す。押し直しは `createPressGuard`、確かめる画面に出す名前は `portalConfirmName`（標準のポータルと同じ lookup）。ポータルの移り方（`PortalNavigate`）は移る流れが終わると解決する Promise を返す。確かめる画面（`components/ui/confirmGate.ts`）は一度に 1 つで、後から来た確認が前の確認を false で閉じる。スクリプトはボタンにした UI があると部屋では描かず、エディタでだけ右下に名札を出す。押せない四角とテキストは下のものの操作を邪魔しない（`pointer-events: none`）。
- ポータルの移り方は `world/portalNavigation.ts` の context で、SNS の画面（`InstancePage`）だけが渡す。world.html とエディタのプレビューでは押せない（`src/world` から router と backend を読まない規則）。
- 画像: `services/worldAssets`（規則）・`routes/assets`・`world_assets`（migration 0045）。画像の作り直しはプロフィール画像と同じ `processImage`（長い辺を縮める `inside`）。
- 使われていない画像の掃除: `services/worldAssets/worldAssetSweep.ts`（起動の 1 分後と 6 時間ごと。reaper のリースを持つ 1 台だけ）。使われているかは `worldAssetRepository.removeUnreferenced` が、全部の定義から shared の `WORLD_ASSET_REFERENCE_PATTERN` でハッシュを 1 回で抜き出して決める（画像ごとに定義を探すと、画像の数 × 定義の大きさになる）。定義を書くトランザクション（`worldRepository.saveDraft`・`publish`）は最初に参照のロック（`worldAssetReferenceLock.ts`）を共有で取り、掃除は 1 回ごとに排他で取ってから消す。掃除が読んだ後にコミットした保存が指す画像を消さないため（掃除の間に来た保存は、その回のコミットを待つ）。定義を書く処理を足すときは同じロックを取る。
- 上げた画像の一覧: 設定の「ストレージ」（`components/hud/tabs/settings/StorageSection.tsx`、API は `GET /api/v1/users/me/storage`・`PUT /api/v1/users/me/storage/settings`、規則は `services/storage/storage.ts`）。使っている量・画像（自分のワールドの下書き・版のどれかで使っていればそのワールド）・自動で消すか（`user_settings.world_asset_auto_cleanup`、migration 0046）。一覧は 50 個ずつ（新しい順・同じ時刻はハッシュ順の続きの位置。合計と数は SUM・COUNT で別に引く）。消すのは 1 個ずつ（`DELETE /api/v1/assets/<hash>.webp`）か、チェックしてまとめて（`POST /api/v1/users/me/storage/files/delete`。1 回 100 個まで）で、自分のワールドで使っている画像があるときだけ確かめる。消す回数はアップロードと別に数える（容量を越えたら消してから上げ直すため）。
- 「使用中」は自分のワールドだけを見る（だれのワールドで使っているかを毎回数えると、全部の定義を読むことになるため）。そのため、ほかの人のワールド（複製したもの）が使う画像は一覧では使っていないように見え、消すとそのワールドでも出なくなる。確かめる文と一覧の上に一言書く。反対に、掃除はだれのワールドで使っていても消さないので、その画像はほかの人が使う間は残り、持ち主の容量に数える。種類（今はワールドの画像だけ）を足すときは shared の `StoredFile` に足す。
- 1 人あたりの容量: `storage_settings`（1 行。migration 0046）・`services/storage/storageQuota.ts`・`GET`・`PUT /api/v1/admin/storage`。アップロードのたびに読む（backend が複数台でも、変えた直後から効く）。
- 圧縮の選び方: `services/profiles/images/webpEncoding.ts`（プロフィール画像も同じ）。
- エディタ: `entityKinds.ts` に部品を宣言し、画像の欄（`image`）は「画像を上げる」ボタン付き（`ImageUrlInput`）。ワールド情報の背景の画像とサムネイルも同じ欄。サムネイルは「画面から撮る」で、エディタの画面を部屋で見える通りに描いて撮れる（16:9 の枠。DOM を描き直すので mod の UI も写る。ほかのサーバーの画像は CORS で読めるものだけ）。

## 残り

- エディタで、上げた画像の一覧から選ぶ（今は毎回上げる。同じ画像なら上げ直しで猶予を数え直す。選ぶ動線を足すときは、選んだ時にも猶予を数え直す）。
- 管理者が画像を消す手段（通報への対応）。今はアカウントを消すと、その人の画像も消える。
- ポータルから部屋へ直接入る（人の多い部屋を選ぶ）かは、Home に置いて使ってから決める。
