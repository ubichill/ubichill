# 二段階認証

認証アプリ（TOTP）とバックアップコードによる二段階認証の設計。フェディバースのログインとアカウントの設定は [フェディバースログインと認証設定](fediverse-sign-in.md) を参照。

## できること

- 設定の「アカウント」→「二段階認証」で有効にする。
  1. QR コード（読めなければ鍵の文字列）を認証アプリに登録する。
  2. 表示された 6 桁のコードを入れる。
  3. バックアップコードが 10 個出る。
- 有効にすると、ログインのたびに認証アプリのコードかバックアップコードを求める。パスワードでもフェディバースでも同じ。
- 「無効にする」「バックアップコードを作り直す」には、今のコード（かバックアップコード）が要る。

## 決めたこと

| 決めたこと | 理由 |
| --- | --- |
| すべてのログイン方法に求める（フェディバースも） | ログイン方法の追加にはパスワードを求めない。奪われたセッションで攻撃者のフェディバースのアカウントを足されても、二段階目で止める。外部サーバーの安全性に頼らない。 |
| 始めるのは直近の本人確認の後だけ（`requireRecentAuth`） | 奪われた古いセッションで攻撃者の認証アプリを登録されると、本人がログインできなくなる。パスワードのある人はパスワード、無い人は 10 分以内のログインで確かめる。 |
| 無効にする・作り直すにはコードが要る | 奪われたセッションだけでは外せないようにする。 |
| 「この端末を信頼する」は作らない | セッションは 7 日で、使っている間は延びる。ログインの回数は多くない。 |
| 有効にしても、今のセッションは残す | 「ログイン中の端末」で見て切れる。 |
| 認証アプリとバックアップコードの両方を無くしたら、自分では戻せない | メールで戻せるようにすると、メールが弱い所になる。管理者による解除はまだ無い（下の「残り」）。 |
| better-auth の twoFactor プラグインは使わない | プラグインが二段階目を求めるのは `/sign-in/email` などだけで、フェディバースのログインに組み込めない。二段階目の後に作るセッションに、一段階目の情報（`password_verified_at`・`auth_account_id`）を引き継げない。プラグインの無効化はパスワードで行い、コードを求めない。 |

## 仕組み

### ログイン

一段階目を通っても、セッションはすぐには作らない。代わりに次のようにする。

1. 「途中」（`two_factor_challenges`）を作る。
2. ブラウザーに乱数を渡し、DB にはその SHA-256 だけを置く。乱数は署名付き・httpOnly のクッキーに入れ、`/api/auth/two-factor` にだけ送る。
3. `POST /api/auth/two-factor/verify` でコードを確かめてから、セッションを作る。

作るセッションには、一段階目の情報を引き継ぐ。

- パスワードで通ったら `password_verified_at` を付ける（管理者の操作に要る）。
- フェディバースで通ったら、どの外部アカウントで入ったか（`auth_account_id`）を残す。その外部アカウントを外すと、セッションも「途中」も消える。

一段階目ごとの組み込み方:

- **パスワード（`/sign-in/email`）:** better-auth が作ったセッションを、後処理で消してから「途中」を作る（`lib/twoFactorPlugin.ts`）。
  - multiSession より前に置き、消したセッションを「このブラウザーのアカウント」に覚えさせない。
  - 「アカウントを追加」の途中なら、元のアカウントのクッキーを戻す。
- **フェディバース:** callback と登録で、セッションを作る代わりに「途中」を作る。画面は `/auth?two_factor=1` に戻し、通ったら元の戻り先へ移る。

### 総当たり・使い回し

| 守るもの | 方法 |
| --- | --- |
| 1 つの「途中」 | 10 分・5 回まで。回数はコードを確かめる前に数えるので、同時に送っても超えられない。 |
| ログイン | 続けて 10 回間違えると止める。止める長さは 15 分から倍にしていき、24 時間まで。止めるたびに連絡先に知らせる。成功すると回数を 0 に戻す。 |
| 設定での間違い | ログインを止める回数には数えない（奪われたセッションで、本人の新しいログインを止めさせない）。代わりに 1 時間に 5 回までに絞る。 |
| 同じコードの使い回し | 同じ時間の区切りのコードは 2 回受け付けない（`last_used_step`）。時計のずれは前後 30 秒まで許す。 |
| 同時の確かめ | ユーザーの行を `FOR UPDATE` で押さえて 1 つずつ確かめる。バックアップコードも 1 回しか使えない。 |

### 鍵の保存

- **認証アプリの鍵:** AES-256-GCM で暗号化する。
  - 鍵はサーバーの秘密から HKDF で作る。
  - 追加の認証データにユーザー ID を入れ、行を別のユーザーに写しても開けないようにする。
- **バックアップコード:** HMAC だけを持つ。平文は表示した 1 回だけ。
- **秘密の入れ替え:** どちらの値にも、どの秘密で作ったかの指紋を残す。
  - better-auth の `BETTER_AUTH_SECRETS`（`"2:新しい秘密,1:古い秘密"`）で入れ替える。新しく作る値は先頭の秘密を使う。
  - 古い秘密を一覧に残している間は、前の値も読める。外すと、その秘密で作った二段階認証は使えなくなる。
  - `BETTER_AUTH_SECRET` だけを差し替えてはいけない。

### 通知（連絡先メール）

次のときに送る。

- 有効にした
- 無効にした
- バックアップコードを作り直した
- バックアップコードでログインした（残りの数）
- 続けて間違えられてログインを止めた

## 残り

- **パスキー（WebAuthn）:** 二段階目として、またはパスワードなしのログインとして。
- **管理者による解除:** 認証アプリとバックアップコードの両方を無くした人のため。本人確認の方法を決めてから作る。
- **本物での確認:** 本物の認証アプリ（Google Authenticator など）での読み取りと、本物のメールの送信。プレビュー環境で確かめる。手元では、OS の QR の読み取りと別実装の TOTP で確かめた。
