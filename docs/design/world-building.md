# mod を書かずにワールドを組み立てる（設計書）

ワールドを作る人が、本体の部品とプレハブを置いて設定するだけでワールドを作れるようにする。条件や変数のような仕組みはブラウザで作らせず、mod（コード）に任せる。[ワールドの部品と画像](world-parts.md)（イメージ・テキスト・ポータル）の続き。

## 目指すこと

作る人を 3 つに分け、それぞれに道具を用意する。

| 作る人 | すること | 道具 |
| --- | --- | --- |
| 置く人 | 部品とプレハブを置き、位置・大きさ・設定を変える | ブラウザのエディタ |
| 組む人 | 部品を組み合わせてプレハブにし、公開する | ブラウザのエディタ |
| 書く人 | 新しい動きを Component として書き、package で配る | CLI と SDK（mod） |

書く人の Component は、エディタの設定欄（`dataFields`）とほかの Entity の参照（`entityRef`）で、置く人がそのまま使える（Unity でスクリプトをインスペクタで設定するのと同じ形）。この仕組みは今もある。足りないのは、よく使う動きの部品と、ブラウザでプレハブを作って配る道。

### 完了の基準

1. コードを書かずに、ブラウザだけで次のワールドを作れる: 背景、案内の看板、押すと開く扉、ワールドの中の別の場所へ飛ぶボタン、部屋に入ったとき最初に見せる場所。
2. 作った組み合わせ（扉など）をプレハブとして公開でき、ほかのサーバーの人がエディタのアセット欄から置ける。
3. Ubichill Home がこれらだけで作ってあり、見本になる。

## 決めたこと

| 決めたこと | 理由 |
| --- | --- |
| ブラウザでできるのは、置く・大きさを変える・設定する・ほかの Entity を指す・親子にまとめる・プレハブにするまで。条件分岐・変数・順番の実行・イベントの配線は作らせない | 配線の仕組みは、育つほど読みにくいプログラミング言語になる（VRChat はコードを書かないトリガーをやめ、Udon に置き換えた）。それが要る動きは mod で書き、Component・プレハブとして配れば、置く人は設定するだけで使える。 |
| 部品が働く場所・範囲・大きさは Entity の transform から取る。部品の data に座標を持たせない | 画面で動かし、広げた通りに働く。数字を打たせない。親子にした一式はまとめて動く。 |
| 「どこへ」「どれを」は、ほかの Entity を指して決める（`entityRef`） | 行き先も、印の Entity を置いて指すだけ。プレハブを置くたびに参照を付け替える仕組みはもうある。 |
| 本体の部品（`core:*`）に入れるのは、本体の権限が要るもの・ほとんどのワールドで使うもの・ほかの部品から指される土台だけ。ゲーム固有の動き（得点・クイズなど）は mod | 本体の部品は、ずっと面倒を見続ける約束になる。mod は版を上げて作り直せる。 |
| 部屋で共有する状態は、インスタンス（Go）が本体の規則で持つ。クライアントは「押した」を伝えるだけ | 今は本体の部品の Entity をクライアントから書き換えられない（`entity:patch` が断る）。状態の計算をサーバーに置けば、2 人が同時に押しても二重に切り替わらない。 |
| プレハブはブラウザで作り、作者のサーバーから package として配る。1 つのプレハブが 1 つの作品 | CLI のプレハブと同じ形なので、置いた後の更新・Unpack・作者の確認・カタログ・版がそのまま使える。作品の単位を mod と揃え、探す・入れる手順を 1 つにする。 |
| ワールドを読む側は、知らない本体の部品と項目を断らずに残し、使わない。書く側（エディタ・CLI）は今まで通り厳しく確かめる | 部品を足すたびに、古いサーバーでワールドを開けなくなるのを止める。知らないものは実行も描画もしないので危なくない。 |

## 部品と transform

今あるもの:

- Entity は transform（`x`・`y`・`z`・`w`・`h`・`scale`・`rotation`）を持つ。Component は transform を上書きでき、省略すると Entity のものを使う。
- 子の Entity の位置は親が基準。エディタの Hierarchy で親子にできる。
- 見た目の部品（イメージ・テキスト・ポータル・`core:ui`・`core:media`）は Entity の矩形に描く。当たり判定（`core:collider`）は Entity の大きさを使える（`size: 'entity'`）。

新しい部品の規則:

| 部品の種類 | transform の使い方 |
| --- | --- |
| 範囲を持つもの（押せる範囲・音が届く範囲） | 自分の Entity の矩形 |
| 場所を示すもの（最初に見せる場所・ワープの行き先） | 指した Entity の中心 |
| 対象を持つもの（スイッチで見え隠れさせるもの） | 指した Entity とその子 |

## 最初に足す部品

部屋の中の人は、カーソル（アバター）と画面のスクロール位置で表される。部品はこれに合わせる。

| 部品 | 型 | 設定 | 何が起きるか | 状態の範囲 |
| --- | --- | --- | --- | --- |
| スポーン | `core:spawn` | なし | 部屋に入ったとき、この Entity が画面の中心に来るようにスクロールする。複数あればどれか 1 つ。部屋では描かない | 本人だけ |
| ワープ | `core:warp` | 行き先（`entityRef`）・表示する文字・見た目 | 押すと、行き先の Entity が画面の中心に来るようにスクロールする | 本人だけ |
| スイッチ | `core:switch` | 対象（`entityRefArray`）・表示する文字・見た目 | 押すと、対象の見える・見えないを切り替える | 部屋の全員 |
| 音 | `core:sound` | 音のファイル・繰り返すか・音量 | 画面の中心が自分の Entity の矩形の中にあると聞こえ、外では離れるほど小さくなる（どこまで届くかは 5 で決める） | 本人だけ |

- **見える・見えない**: Entity に `visible`（既定は見える）を足す（Unity の active と同じ。部品にすると、見え隠れさせたい Entity ごとに部品を足すことになる）。エディタの設定欄は「最初から見せる」。見えない Entity とその子は、描かず、押せず、当たり判定もしない。mod の Worker は止めず、シーンの読み取りで見えるかどうかを読めるようにする（SDK に足すだけ）。
- **スイッチの状態**: インスタンスが Entity ごとに「見えるか」を持つ。`core:switch:press` を受けると、押されたのが `core:switch` の Entity か、対象がその部屋にあるかを確かめてから切り替え、全員に送る。部屋ごとの状態で、部屋が無くなれば最初に戻る。押す回数は人ごとに絞る。
- **音のファイル**: 画像と同じ置き場所に、音（Ogg Vorbis・Opus・MP3）も上げられるようにする。作り直しはせず、形式を中身で確かめ、長さと大きさに上限を掛ける。ブラウザは操作の後でないと音を出さないので、部屋に入る操作の後に鳴らし始める。
- **UI とスクリプト**: UI（`core:ui`）は Entity の大きさの四角（塗り・枠線・角丸・テキスト）で、FigJam の図形と同じ考え方。「ボタンにする」と押せるようになり、同じ Entity のスクリプト（ワープ・スイッチ・ポータル）が押したときに動く（扉の絵の上に塗りなしの UI のボタンを重ねれば、扉を押すとワープ）。ボタンにした UI が無ければ、スクリプトは標準のボタンを出す（置いてすぐ押せる・前の版のワールドの見た目を変えない）。HTML 風の UI データ（`markup`）は上級者向けとして UI に残す。汎用の UI を組み立てる道具はブラウザに作らない（四角とテキストとボタンまで）。
- **ポータルとの違い**: ポータル（`core:portal`）はほかのワールドへ移る（今の部屋から出る）。ワープはワールドの中で見る場所を変えるだけ。ポータルに項目を足さず型を分けるのは、知らない項目を断る古いサーバーでもポータルが開けるようにするため。

足さないもの:

- **エリア（カーソルが入ったら何かする）**: カーソルは手の位置で、体の位置ではない。触れただけで動くのは使いにくい。要る人は mod で作る。
- **タイマー・数を数えるもの・条件**: 「決めたこと」の線の外。mod で書く。

## プレハブを作る・配る

今あるもの: package の `prefabs/` に書いたプレハブを、エディタのアセット欄から置ける。置いたものは元との関連を持ち、元の版が上がると差分を見て更新でき、Unpack で関連を外せる（[mod package を作る・使う](../MOD.md)）。ただし作れるのは CLI で package を作る人だけ。

足すもの:

1. **作る・公開する**: エディタで Entity（子を含む）を選び、「プレハブとして公開」。名前・説明・見た目の画像（上げた画像）と、一覧に出すかを決める。作者のサーバーに package として保存し、ワールドの公開と同じく、ブラウザの公開環境の鍵で署名する。選んでいた Entity は、そのプレハブの配置になる。
2. **版**: 配置からもう一度公開すると版が上がる（同じ版は上書きしない）。ほかの人の配置は、今と同じく差分を見て更新できる。
3. **探す・置く**: アセット欄に「プレハブ」を足し、mod 管理と同じタブ（使用中・ローカル・グローバル）で探す。作品の参照 `@作者@サーバー/ID` や共有ページの URL でも入れられる。
4. **ほかの mod を使うプレハブ**: package に、使う mod とその版（作者と manifest の hash）を書く。置くとき、ワールドに無い mod は、mod 管理で足すときと同じ確認（作者・権限）を通して足す。今の「別の package の依存は扱わない」を「書いた依存だけ扱う」に変える。
5. **画像**: プレハブの中の画像は、作者のサーバーの画像の URL を指したまま配る。

| 決めたこと | 理由 |
| --- | --- |
| 置き場所は作者のサーバーの Postgres（画像と同じ） | ブラウザで作る人は配布先（GitHub Pages など）を持っていない。プレハブは小さい（1 つ 100 KB、manifest は 1 MiB まで）。 |
| 配る形は CLI の package と同じ | 置いた後の更新・Unpack・作者の確認を作り直さない。CLI の人も `ubichill prefab add` で使える。 |
| 画像は写さず、作者のサーバーを指す | 配置のたびに、置いた人の容量に数えない。そのかわり、作者がアカウントを消すと画像も消える（「決めていないこと」）。 |

## 互換

- **知らない本体の部品・項目**: 今は、ワールドの検査（frontend・backend・loader が共有する shared の schema）が、知らない `core:*` と、本体の部品の知らない項目（`.strict()`）を断る。読む側では、これらを残したまま使わないように変える。部屋では「このワールドの一部は、このサーバーでは使えません」と出す。エディタは保存のときに残し、CLI とエディタは書き間違いを見つけられるよう問題の一覧に出す。この変更より前のサーバーは断るままなので、部品を足し続ける前に入れる。
- **mod に入る部品の一覧**: SDK は本体の部品の種類の一覧（`CORE_COMPONENT_TYPES`）を mod に埋め込むので、部品を足すと、一覧を使う公式の mod の中身が変わる。公式の mod の版を上げれば済み、上げ忘れは CI が止める（#387 で danmaku を 1.0.5 にした）。ほかの作者の mod は、作り直すときに新しい版で出すので困らない。SDK の形は変えない。
- **インスタンスとのやりとり**: スイッチの状態は新しいメッセージで送る。フロントとインスタンスは同じサーバーが一緒に配る内部の API なので、互換は残さない（[約束ごとの分類](../PROTOCOLS.md) の D）。
- **ワールドの形式**: Entity の `visible`、新しい部品、プレハブの package の依存は、どれも項目を足すだけ（分類の A）。

## 部屋で置くポータル

ワールドの作者が置くポータルとは別に、部屋にいる人はだれでも、どのワールドの部屋でも、ランチパッドからポータルを開ける。

- **行き先は部屋**: ワールドに置くポータルは行き先のワールドのパブリックの部屋へ入る（人のいちばん多い部屋。下の「ワールドに置くポータルと公開範囲」）。部屋で置くポータルはその部屋へ行くので、後から通った人も同じ部屋に入る（招待のみ・フレンドの部屋にも、入れる人なら行ける）。
- **開き方**: 部屋の中で新しいインスタンスを作るとき「入る」か「ポータルを置く」かを選ぶ（ワールドの詳細・インスタンスの詳細・インスタンスのタブ。選ぶ前には作らない）か、部屋の詳細の「ここへのポータルを開く」。見ている所の真ん中に出る。
- **インスタンスが作る**: `portal:open` を受けたインスタンスが `core:portal` の Entity を作って全員に配る（data は `room`・`expiresAt`・`ownerName`。ワールドに置くポータルとは項目が違うので取り違えない）。利用者が core:* を作る・動かす・消すことはできないまま。閉じられるのは置いた人だけ（`portal:close`）。
- **数と時間**: 1 人 1 つ（置き直すと前のものは消える）。60 秒で消える。置き直しは 3 秒あける。1 つの部屋に 64 まで。置いた人が部屋を出ても消さない（置いた人が先に通り、ほかの人が後から来るのがふつうの使い方）。数字は shared の `ROOM_PORTAL` と Go で同じにする。
- **新しい部屋を残す**: ポータルの先に作った部屋は、作った人が入らないまま待つ。空の部屋はふだん 5 秒で消えるので、作るときに `holdEmptyMs` を渡し、ポータルが消えるまで（`held_until`）空でも消さない。
- **入れるかは見る人ごと**: 公開範囲・招待・満員で入れない部屋は、その人の画面では鍵を出して押せない。無い・見えない部屋も押せない。
- **ほかのサーバーの部屋**: 行き先は部屋のサーバーから見た住所で書き、ほかのサーバーから来た人の画面は部屋のサーバーのドメインを付けて読む。ほかのサーバーの部屋にいる間は置けない（ランチパッドの部屋は自分のサーバーから見た住所だが、自分のサーバーのドメインを画面が知らない）。
- **ワールドの作者は止められない**: どのワールドでも使えるものにした。困る例が出たら、止める設定を足すかを決める。
- **プライベートのワールドの部屋**: 部屋を作った人だけがポータルを置ける（プライベートのワールドの部屋は作者しか作れないので、作者が自分の部屋に人を呼ぶ形）。置いたあとの入れるかは、部屋の公開範囲で決まる（URL で入るのと同じ）。
- **置く許可はサーバーが決める**: インスタンスは行き先の住所の書式しか分からないので、backend が置いてよいかを決めて許可を出す（`POST /api/v1/room-portals/grants`、body は `portal:open` に送るのと同じ住所 `{room}`）。
  - backend は住所を自分のドメインで読み、このサーバーの部屋なら部屋を引く（無ければ 404）。部屋のワールドの**いまの**公開範囲（部屋を作った時の値ではない）を解決し直し、プライベートで部屋を作った人でなければ 403。ワールドを確かめられなければプライベートとして扱う。ほかのサーバーの部屋は許可する（入れる人は部屋のサーバーが決める）。
  - 許可は `base64url(JSON {room, userId, exp})` + `.` + `base64url(HMAC-SHA256(鍵, 前半))`。鍵は `HMAC-SHA256(管理トークン, "ubichill room portal grant v1")`（チケットの鍵と同じ派生の仕方で、用途の名前だけ違う。backend は `INSTANCE_TICKET_KEY` を知らないので、いつも管理トークンから派生する）。有効は 60 秒（shared の `ROOM_PORTAL_GRANT`）。
  - インスタンスは、管理トークンのある運用では `portal:open` の `grant` を確かめる（`room` が送られた住所と同じ文字列・`userId` が送り手・期限の前・署名を一定時間で比べる）。単体モード（管理トークンが無い）では求めない。形は TS と Go の両方のテストに同じ例を置いて固定している。
  - 画面の「ここへのポータルを開く」を出さない判定（`canOpenRoomPortalTo`）は、押せない人にボタンを見せないためだけに残す。

## ワールドに置くポータルと公開範囲

- **ワールドに置くポータルはずっと置いたまま**: 寿命は無い（作者がワールドに書く）。押すと行き先のワールドのパブリックの部屋に入る。見る人がそのまま入れるパブリックの部屋のうち人のいちばん多い部屋を選び（散らばらない）、無ければパブリックの部屋を作る。部屋は画面が既存の一覧の API で選び、無いときだけ作成の API を呼ぶ（入るだけの人を作成の回数制限に数えない）。同時に通った人がそれぞれ部屋を作ることはある（次に通る人は人のいる方へ集まる）。作った部屋は入るまで 30 秒は空でも消さない（今の部屋を出る・署名なしの確認の間に消えないように）。
- **ワールドの公開範囲**: このサーバーのワールドは「パブリック」か「プライベート」。作者がエディタの「公開する」の上で選び、その場で変わる（署名した中身には入れず、サーバーの `worlds.visibility` に持つ。ほかのサーバーへは、一覧に出さないことと、ワールドのファイルのヘッダーで伝わる）。
  - パブリック: だれでもインスタンスを作れ、一覧（ほかのサーバーへの一覧・お気に入り・プロフィール）に出て、ワールドに置くポータルの行き先にできる。
  - プライベート: インスタンスを作れるのは作者だけ。一覧に出さず、ワールドに置くポータルの行き先にできない（作者が自分のワールドに置いても、鍵を出して押せない）。作者が作った部屋には、URL・部屋で置くポータル・招待で入れる。ワールドのページと詳細は URL を知っていれば見える（中にいる人の画面が使う）。
  - 公開（署名した版）するまでは、どちらに設定していてもプライベート。既定はパブリックなので、公開すればすぐ置ける（CLI で公開しても同じ）。0047 の前からあるワールドもパブリック。
  - ホームをほかの人のプライベートのワールドにはできず、ホームのワールドがあとからプライベートになったら既定のワールドで入る。
  - 外部（URL）・同梱のワールドは公開範囲を持たない（パブリック）。ほかの ubichill のサーバーのワールドは、そのサーバーが知らせた公開範囲に従う（下）。
- **公開範囲で保証すること**: プライベートのワールドの部屋を作れるのは作者だけで、作れるのは作者のサーバーでだけ。ubichill のサーバーはこれをサーバーの側で守る。
  - 作者のサーバー: 作者でない人の部屋の作成を 403 にする（`canStartInstance`）。ワールドのファイル（`.yaml`・`.lock.json`・`.sig.json`）には `Ubichill-World-Visibility: private|public`（公開の有無を含めたもの。`Access-Control-Expose-Headers` にも入れる）を付ける。リポジトリのワールドには付けない（パブリック）。
  - ほかのサーバー: 外部のワールドの URL を解決するとき、このヘッダーが `private` ならそのワールドを `visibility: 'private'` にし、作者の ID を持たせない（このサーバーのユーザーと一致しないので、だれも部屋を作れない・ワールドに置くポータルは鍵・一覧に出ない）。無い・知らない値はパブリック。自分のサーバーの URL は今までどおり DB のワールドとして解決する（作者は作れる）。
  - 公開範囲は取ってきた URL ではなく**署名の作者**で決める（ファイルは誰にでも配るので、署名ごと別の場所に置き直せる）。外部のワールドの署名の作者（`acct:<ID>@<ドメイン>/<名前>`）が
    - このサーバーのアカウント: その作者のワールド（以前の名前を含む）の今の公開範囲と作者の ID を当てる（作者は写しからでも作れ、ほかの人は作れない）。
    - ほかのサーバーのアカウント: 作者のサーバーの正規の URL（`https://<ドメイン>/api/v1/authors/<ID>/worlds/<名前>.yaml`）のヘッダーを見る（外部のワールドと同じく 5 分覚える）。取ってきた URL が正規の URL ならそのヘッダーのまま。
    - 正規の URL が無い（消した・名前を変えた先で古い名前をたどれない）・つながらないときはパブリックとして扱う（閉じない）。署名を外して置き直せば別の（未署名の）ワールドとして部屋を作れるので、ここを閉じても守れる範囲は広がらず、作者のサーバーが落ちている間に公開のワールドの写しまで止めるほうが困るため。作者の鍵の確認も、つながらない間は「確認待ち」で通している。
  - 外部のワールドの解決結果は 5 分覚えるので、作者が公開範囲を変えてから、ほかのサーバーで効くまで最大 5 分かかる（取り直せない間は前の結果のまま）。作者のサーバーの中では、変えたときにすぐ効く。
- **保証しないこと**:
  - 中身を秘密にすること。ファイルは誰にでも配る（作者の部屋に入る人の画面と、ほかのサーバーからの来訪者がワールドを読むのに要る）。URL を知っている人・部屋に入った人は定義を読める。URL・部屋のポータル・招待で作者の部屋に入るのは今までどおり。
  - プライベートにする前に取得された写しを取り消すこと。
  - ヘッダーを知らない古い版の ubichill のサーバー・ubichill でない実装が守ること（古い版のサーバーは、そのワールドの部屋を作らせる）。
  - 署名を外して置き直した写しを止めること（中身は同じでも、署名の無い別のワールドとして扱う。一覧には出ず、入る人には未署名の確認が出る）。

## 実装する順番

| 順 | すること | 理由 |
| --- | --- | --- |
| 1 | 読む側を寛容にする（知らない本体の部品・項目を残して使わない） | 2 以降で部品を足すほど、これより前のサーバーで開けないワールドが増える。 |
| 2 | スポーン・ワープ・見える/見えない・スイッチ | 本人だけの部品はインスタンスに触らないので先に出せる。スイッチはインスタンスの状態と一緒に。 |
| 3 | Ubichill Home を作り直す | 2 までの部品で、看板・扉・ワープ・スポーンを置き、見本にする。 |
| 4 | プレハブを作る・公開する・探す（依存付きを含む） | Home で使った組み合わせを、最初の公式のプレハブとして出す。 |
| 5 | 音と、音のアップロード | 音の形式の確かめ方と上限は別に決めることが多い。 |

## 決めていないこと

- 見えない Entity を mod にどう見せるか（SDK に足す項目の名前と、見えなくなったときに知らせるか）。今は mod からは見えるかどうかを読めない（描画と当たり判定は Host が止める）。
- プレハブの見た目の画像を、エディタの今の見た目から自動で撮るか（ワールドのサムネイルは「画面から撮る」で撮れる。撮り方は `captureThumbnail` を使える）。
- 作者がアカウントを消したとき、配られたプレハブとその画像をどうするか（置いた中身は残るが、画像は消える）。
- 管理者がプレハブを配布停止にする手段（カタログの配布停止の状態を使う想定）。
- 音の上限（長さ・大きさ）と、聞く人が音量を下げる設定。
- エディタの元に戻す（undo）と、ひな形から始める機能（この設計の後）。
- ほかのサーバーのワールドへのポータルで、そのサーバーのパブリックの部屋に入るか（今はこのサーバーに部屋を作る。ほかのサーバーに部屋を作る・部屋の一覧を聞く連合の RPC が要る）。
- 部屋で置くポータルを、部屋を作った人がほかの人の分まで閉じられるようにするか。ワールドの作者が止められるようにするか。フレンドの現在地からも開けるようにするか。
