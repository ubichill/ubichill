# フレンドとインスタンスの公開範囲

規則は `packages/shared/src/user/friends.ts`（backend の認可と画面の表示で同じ関数を使う）。

## フレンド

- `user_friends` の 1 行は「userId が friendId に申請した」。承認すると `accepted`。申請の向きは問わず、どちらかの行が
  `accepted` ならフレンド。
- 申請したら相手から申請が来ていた場合は、そのまま承認になる（お互いに申請したらフレンド）。
- 解除・取り消し・拒否は、どれも 2 人の間の行をすべて消す（どちらからでもできる）。
- 検索は ID の前方一致と表示名の部分一致（大文字小文字は区別しない。`%` `_` は文字として扱う）。

## インスタンスの公開範囲（VRChat と同じ考え方）

| 種類 | 一覧・フレンドの現在地に見える人 | 入れる人 |
|---|---|---|
| パブリック | 誰でも（ログインなしでも） | ログインしている人 |
| フレンド+ | 作成者か、参加している誰かのフレンド | 見える人 |
| フレンドのみ | 作成者のフレンド | 見える人 |
| 招待のみ | 一覧に出さない | URL を受け取った人（招待） |

- 作成者と参加している人にはいつも見える。入れない人には、インスタンスがあることも伏せる（404）。
- フレンドの現在地は、自分に見えないインスタンスにいるフレンドを「非公開の場所」にまとめ、どこかは出さない。

## 現在地と在室

- 在室は backend のメモリ（`userManager`）が真で、フレンドの現在地は画面が 15 秒ごとに読み直す（通知はしない）。
  backend を複数台にするなら、在室を共有する仕組み（Redis など）が要る。
- 1 アカウント 1 接続。別のタブ・端末で参加すると、古い接続に `session:replaced` を送ってから切る（画面は理由を出してロビーへ）。
- 通信が切れて自動で再接続したら、クライアントは参加し直す。切断の猶予（`DISCONNECT_GRACE_PERIOD_MS`）とインスタンスの
  片付けの猶予を過ぎてインスタンスが消えていたら、理由を出してロビーへ戻す。

## 画面（HUD のタブ）

- **ソーシャル**: フレンドがいま入っているインスタンスだけ（自分に見えるもの。インスタンスごとにフレンドの多い順で、入っているインスタンスには「ここにいます」）・ユーザー検索・フレンドと申請中の一覧。
- **通知**: 種類ごとのタブ（招待・フレンドリクエスト・その他）。種類は `frontend/src/lib/notifications.ts` の
  `NotificationKind` に足す（招待は #199、メッセージは #198）。未対応の件数を HUD の通知タブに出す。
- **マイページ**: タブバーには出さず、右上の自分のユーザー名を押すと開く（ロビーでもインスタンス内の HUD でも）。
- ユーザーページ（`/user/:id`・`/@ID`）: 共有できるよう、ログインしなくても見られる（操作するときだけログイン）。リンクのプレビュー（名前・アイコン・説明）は BFF が付ける。ほかの人には、フレンドの操作と、フレンドならいまいる場所（合流する）。
