# インスタンスプロトコル v1

HTTPの契約は `openapi.json`、WebSocketのイベント一覧とフレームは `asyncapi.json`。
`pnpm protocol:generate` でGoとTypeScriptのHTTP型を生成する。生成物はコミットし、CIで差分を確認する。
mod SDKのHost/Workerプロトコルとは独立したバージョンである。

## 接続

1. SNSモードではSNSが認証・フレンド・パスワードを検証し、管理APIで対象インスタンスの参加チケットを発行する。
2. 単体モードでは `/realtime/v1/instances/{id}/guest` がゲストIDを発行する。
3. 返されたURLをWebSocketで開き、最初の10秒以内に `world:join` を送る。

```json
{"event":"world:join","id":"request-1","data":{"instanceId":"standalone","token":"opaque-ticket","user":{"name":"Guest","position":{"x":0,"y":0},"status":"online"}}}
```

チケットはURLやCookieに入れない。インスタンス・参加者・期限・種別をHMACで検証する不透明な値として扱う。
署名鍵は起動ごとに生成する。SNSチケットは2分、ゲストの再接続情報は24時間有効。
期限は入室時に検証する。既存接続の継続中にSNSの権限変更を即時反映する機能はない。

## フレームと順序

- 送信: `{event, data?, id?}`。`id` はリクエストごとに一意な100文字以内の文字列。
- 応答: `{replyTo, data}`。join/createとメディア操作は応答必須。patch/delete/leaveもIDがあれば応答する。
- 通知: `{event, data?}`。失敗はリクエストIDがあれば `{success:false,error}`、なければ `error` 通知。
- 入室応答 → `users:update` → `world:snapshot` → 以降の更新、の順番で同じ接続へ送る。
- 同一インスタンスの状態変更と送信キューへの追加を直列化する。ネットワーク書き込みは接続ごとに独立。
- エンティティ作成の応答は作成者へ、created/patch/deleteの通知は他の参加者へ送る（作成者は楽観的更新）。
- 輸送は通常のWebSocket。Socket.IOクライアントでは接続できない。

## 更新と再接続

カーソル・ephemeralは古い情報を破棄できる。各接続のキューは256フレームで、揮発通知は満杯時に破棄。
確定状態の通知を積めない接続は切断し、再接続時のスナップショットで復元する。
クライアントもbufferedAmountが64KiBを超えると揮発送信を止める。

操作の自動再送・オフラインキュー・重複排除は行わない。タイムアウトしたcreate等は結果不明であり、
同じ操作を自動再実行せず再接続のスナップショットで確認する。request IDは応答の対応付けに使う。
再接続では参加チケットを取り直し、最新のローカル位置・ステータスでjoinする。

自動接続は1回の復旧につき最大6回（初回を含む）・30秒で終了する。HTTPが応答しない場合も
30秒で中断し、参加失敗を一度だけ返す。接続が10秒以上安定した後に次の復旧の上限をリセットする。
短時間の入室・切断を繰り返しても上限はリセットしない。退出・ページ離脱では待機中のHTTPと再試行を中断する。
一時的な通信エラーは再試行中として表示し、認可拒否・プロトコル不一致・上限到達だけを確定した失敗にする。
単体モードでは失敗画面に留まり、本人の「再試行する」操作で再開する（ルートへの自動移動で同じ部屋へ戻さない）。

`world:join` の失敗応答には復旧可能な場合だけ `code` を付ける。
`ticket_invalid` は失効・起動時の署名鍵変更等でチケットを検証できない場合で、同じ復旧中に1回だけ取り直す。
`instance_unavailable` はチケット発行後に部屋が消えた場合で、上記の接続上限内でチケットを取り直す。
認可・パスワード・満員等の拒否は再試行しない。

切断後15秒は参加者とロックを保持する。同じIDで戻れば復帰し、期限後にロック解除と退出通知を行う。
明示退出は即時処理。同一ユーザーが別接続から入ると旧接続へ `session:replaced` を通知する。
現在は同一Goプロセス内で1ユーザー1接続を保証する。
`instance:closing` はインスタンスの終了（リーダーの削除・空室の掃除）でのみ送る。Goプロセスの停止では送らずに切断し、
クライアントは再接続して部屋を作り直す（SNSは部屋が無いと観測してから猶予を数えるので、その間に戻れば消えない）。

## 操作の制約

- クライアントはownerId/idを偽装できない。所有者は入室済み参加者IDから決める。
- core:*の更新・作成・削除を拒否する。ワールド初期配置でのみ作成可能。
- 他人のロックは変更できない。ロック取得時はサーバーが参加者IDを設定する。
- ownerIdがあるエンティティの削除は所有者のみ。共有データはロックされていなければ参加者が編集できる。
- エンティティのdata/transformはトップレベルのキーをマージする。
- メディアtimelineはrevisionによる競合検出。同じmediaIdのloadは冪等。
- 受信70KiB、エンティティ64KiB、ephemeral32KiB、240イベント/秒/接続が上限。
- インスタンス最大1000、部屋の参加者最大1000、エンティティ10000、メディアsession1000。
